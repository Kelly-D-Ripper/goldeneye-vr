# Tactical launcher parity audit

Baseline: the working **Tactical 0.18.4-test Progression** package and native source `eecdc0b`. The [source inventory](native-change-inventory.tsv) accounts for all 246 paths changed from the upstream v0.5.25 branch point `c421806`, including tools, tests, platform integration and large shared source files. The audit also checks the default and classic AI launchers. A changed file is not automatically a missing feature: current upstream `mod-system` at `e8445c3` already supplies many of these engine systems. The older [parity notes](PARITY.md#original-audit) hold the detailed model and optic acceptance criteria.

Status is about the current launcher pack: **in pack** means wired, **available** means an upstream API exists but the pack still needs integration or proof, and **gap** means the current APIs cannot preserve the native result. A desktop smoke test, a script-host test and a headset playthrough are separate evidence.

| Native feature or feature family | Current route and exact acceptance gap | Next work |
|---|---|---|
| Gun roster, PPK start, pickup swaps, native item identities | The Lua catalogue and item events are in pack. Borrowed cartridge ids are a temporary adapter with a limited pool. Native physical identities, exact builds on the ground, multiple weapons sharing a cartridge archetype and co-op visibility still need proof. | Keep the mod's instance data in Lua. Test a slot recycling, duplicate archetypes, and equip/drop/redraw on both headsets. Scope native item extensions (C9) only where a carrier cannot keep native behavior. |
| Weapon stats, fire modes, recoil and spread | The pack wires basic damage, rate, capacity and semi/burst/auto logic. `mod.weapon.setStats` now exposes `automatic`, spread, per-gun recoil, ROM shot sound, and hearing ranges. It does not by itself make states independent between two instances of the same cartridge item. Chest grip is a substitute for the native selector. | Port attachment-derived stats and test Glock auto, suppressed hearing, distinct carrier instances, and selector input. Retain native haptics and muzzle/shot origin. |
| Gun bodies, mesh finishes, mounts, action geometry and muzzle | **In pack (static parts).** `tools/export_assemblies.c` links the native `gevr_tactical_gear.c` unchanged and exports all 78 deployable builds (each gun's stock assembly and every named preset). `generate_assemblies.py` composes each mount with the native `gearGunAxes`, matching the Whiteout replay to 2e-5, and drops root choices as native does. `looks.lua` draws the body through `mod.weapon.model` with the native `gearMuzzlePoint` muzzle (#344) and the other parts through `mod.attach`. The magazine hides during a reload. `stage_pack.py` ships the 490 meshes unchanged, each with an `.opaque` list, as native ignores texture alpha. **Desktop evidence (2026-11-25):** on Windows flat (`mod-system` + #344), Dam showed the M4A1 Whiteout assembly from native files and Tactical's PPK. **Still a gap:** moving action parts (bolt, charging handle, slide lock), the magazine part following the seated capacity, the RPG (not in the gear catalogue), guard and remote looks, and borrowed carriers' Gun fit. | Bind action parts to animated nodes or `mod.attach.place` from shot/reload events; check both hands, all 42 guns and the headset. Guards: `mod.attach` with the guard anchor. |
| Hands, sleeves, gloves, grip and support | C10 draws the carrier's stock hand and sleeve; it is not Tactical's fitted glove. Native glove/hand geometry and tracked grip/support poses remain a gap. Existing hand poses, anchors and haptics cover inputs; static attachments do not reproduce pose selection. | Pack hands feature accepted on #291 after C1. Keep native pose selection, left mirroring, support grip location and wrist anchor; check original/Bean/GE-X carrier behavior. |
| Optics, scope lens, red dot, holo, zoom, reticle, parallax, zero, night/thermal and folding magnifier | `mod.weapon.scope(false)` is used to remove the stock optic. Its generic lens does not provide native behavior. Need C1's current draw frame and C2's lens in the same hand draw. Remote folded/deployed state is separately tracked in #335. | Check native PSO-1 live lens, eye position/zero and every optic class; test HHS-1 black and tan, fingertip flip, 1x/3x, haptic and detach/swap. Test remote flip, join and removal separately. |
| Physical reload, chamber, hand magazines and body rig | Loaded rounds and reserve gating are in pack; `reload_attempt`, `reload_end` and the auto-advance veto are wired; the last keeps an empty Tactical gun in hand. Rig counts alone do not reproduce 3 primary / 2 pistol pouches, hand grabs, magazines dropped to the floor, remaining rounds on the mesh, seating, racking or a PKM belt. | Test the empty-gun veto in launcher play and test engine pose/transfer interfaces with C1. Keep physical magazine state in Lua. Validate handling in both hands and the empty chamber versus empty magazine cases. |
| Drops, corpse loot, armour, extraction and co-op ownership | `weapon_dropped`, `item_pickup` and `pickup_removed` now preserve the guard-roster gun identity by pickup ID. The script host verifies two newly acquired primaries come home on success, excluding either one removed from inventory; leaving or dying grants neither. Full build, ammo and magazine metadata, shared drops, exact player-dropped gun identity and native slot gestures remain open. | Wire exact ammo/magazine/build identity, spawns and removal. Test contested pickup and recycled slots on two headsets (#331). Repeat the held and stowed extraction and the failure cases in launcher runtime. |
| Movement, weight and controls | Native carried weight affects move speed; `mod.player.setSpeed` is available. Base engine has input, hand / body anchors and avatar IK; this is not proof of Tactical-specific fits, ergonomics, manipulation thresholds, hand-off/rescue behavior or parity with controller settings. | Port weight calculations to Lua. Compare sprint/strafe, hands, shoulder/hip slots, crouch, grips and hand poses on actual hardware. Keep base avatar/input settings. |
| Saved progression, rewards, unlocks and stats | Pack has PPK start, basic extraction, reserve, basic magazine clears and stats. Reserve eligibility counts every successful clear, including replays, as in 0.18.4; the first clear and every third replay still award a token. Applying a kit mid-mission does not change the ownership snapshot used for gun clears. Folder and difficulty functions are available; the pack now selects `progress-1.txt` through `progress-4.txt` when a folder is known, preserves the old save as a folder 1 fallback, and records clears by selected difficulty. The mission-complete call writes a result; native Unlock All only exposes missions and preserves the underlying records. Native kit/part unlock rules are not wired. | The current script host passed folder migration and isolation; both hosts passed the existing extraction scenarios. Match the remaining reward, extraction, gun stats and mastery details in launcher play. Ask for a general mission availability override if needed; do not fake completed missions. Test RMR/ACOG mount bundles, all Whiteout parts together, 60+ mastery gates and PKM with no magazine unlocks. |
| Loadout, Workshop, Guardian/mission presets, briefs, debrief, editor | The native menu previews the full assembly and shares recipes with the desktop editor. Pack pages show selections and stats, and now each gun's build (the stock assembly or any native preset; a progression save gets the stock build until part kits are ported), but the four-page UI cannot show an interactive gun/guard preview or the complete Workshop. The selection screen must reflect the saved attachments. | Keep recipes/editor in mod tools; scope preview/layout support after C1. Exercise Done → saved assembly shown; one PPK with suppressor attachment; both M4 Pine presets with rear sight removed. Cover first-run choice before mission where the native build asks it. |
| Campaign placement, armour, outfits, rifles, guards and reinforcements | `guard_spawning`, `mod.guards` placement/paths and guards' part anchors are available. Pack has basic roster and reinforcement rules. Native armour tiers, KLMK vest, helmet/body variants, Facility fit, authored sentry/pair/post/patrol layouts and all closed-map entries are unverified or absent. | Port data and validate every mission, difficulty, room and archetype. Preserve authored loadout, body/armour, part fit, safe spawn, mission scripts and classic AI variant. |
| Combat AI: cover, peek, assault/support/flank squads, alert facing and corpse discovery | Alert and guard path primitives are available. Native role transitions, suppression/cover, navigation/room queries, facing while firing, pairing, seeing bodies and alerting nearby squads are not equivalent to a chase script. | Derive reusable sensing/cover/AI action hooks and use Lua for Tactical tactics; check native and classic modes. Reproduce crouched aim at player and corpse reaction. |
| Smoke, wounds, gore, blood, blade cuts, head bursts, ragdoll and FX | `mod.effect` currently plays base smoke at named anchors. No corresponding pack hooks for the native hit surface/normal, blood stains, cut wounds, debris and HollywoodFX/BloodyCombat. Base effects or upstream fixes are not the Tactical effect assets or trigger rules. | Keep pack data and options; scope shared impact/FX hooks with hit data and a deterministic co-op event path. | Sounds, spatial audio and haptics | `mod.audio.play`/`playAt` cover ROM sounds; the gun stats sound field takes a ROM id. Native external sound assets, handling/audio cues and their attenuation/occlusion need a pack sound route. Stock spatial audio, audio mix and haptics can be reused. | Audit asset-to-event tables; port ROM-backed cases first, then propose pack sound loading to the existing mixer. | Blades, scabbards, watches, gadgets, detonator and range | Huntsman/katana, separate scabbards, watch gauges, detector/decoder hand use, detonator/mine counts and private range are native features. Keep mission-objective identity through held use. Inventory/stow state for drawn knives/swords and their replica appearances must match. |
| Guided trigger throws: mines, RPG where applicable, and mission gadgets | `throwSpeed`, `throwLift` and styled `throwGuide` are available for supported cartridge items, including the object path. Native visual asset/hold and exact behavior are not automatically supplied. | Wire existing stats and verify mine, mission bug, final remote detonator, ammo consumption, ordinary grip throw and line-to-flight match on headset (#331). |
| Co-op, player state, lobby and remote gear | `mod.net`, native player slots, damage/revive events and shared pickups exist. Pack sync is partial. Test host/guest, late join, reconnect and swap; distinguish built-in transport from running both headsets. |

## Order of work

1. Land C10 (#334). The follow-ups add the normal-suite tests and fix the floating PP7 tube in the stock hand pass. Bean visual acceptance is open. Keep the native build as a baseline.
2. Prepare and validate authored attachment frames and animation (C1), then lens/optic behavior (C2) and fitted pack hands under the accepted dependency order. Do not submit C1 against an upstream base missing C10, and do not describe the ordinary C10 replay as a finished pack.
3. Independently wire documented APIs into Lua in small changes: folder and difficulty, weapon stats/auto-advance, drop identity, throws, guard paths and weight. Move only reviewable, cross-mod engine additions upstream. Discuss general hooks in the existing requirements thread before opening duplicate issues.
4. Track the acceptance gap until each native feature is demonstrated in the launcher build. A gameplay regression in a packaged launcher run keeps that row open even if isolated tests pass.
